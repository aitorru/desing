# Dot

**Dot** es un lenguaje de diseño hecho de puntos: tokens CSS, unos treinta componentes React y
este Storybook. No te va a cambiar la vida. Lo que sí hace bien es lo aburrido: paneles de
estado, informes de plataforma, post-mortems y consolas internas que se leen de un vistazo, de
día y a las tres de la mañana.

## Cuándo usarlo

- **Sí:** el panel de estado de servicios, la pantalla de despliegues, el informe semanal de
  plataforma, el post-mortem de un incidente, la revisión mensual del coste de nube.
- **También:** cualquier herramienta interna que necesite verse decente sin un diseñador al lado.
- **Mejor no:** una app de consumo con marca propia, o si buscas un sistema con doscientos
  componentes. Aquí hay los justos.

## Lo que trae para operaciones

| Componente | Para qué |
| --- | --- |
| `Status` | Estado como punto + palabra: correcto, degradado, caído, en curso, sin datos |
| `DataTable` | La tabla de servicios: orden por columna, cifras en mono, fila seleccionada |
| `Diagram` | El camino de una petición: servicios, almacenes y colas unidos por puntos |
| `Pipeline` | Compilar → probar → desplegar, con el tiempo de cada etapa |
| `KeyValue` | Commit, rama, imagen, región: metadatos con guía de puntos |
| `CodeBlock` · `LogView` | El YAML del rollout y el registro, en IBM Plex Mono |
| `DotUptime` | Disponibilidad por día como tira de puntos; solo los días malos llevan color |
| `Stat` | El KPI (p95, error budget, MTTR) con su gráfico de puntos |
| `DotProgress` · `DotBars` · `DotLoader` | Progreso, series cortas y «estoy en ello», sin spinners |
| `Callout` | Avisos: mantenimiento, servicio caído, datos de ejemplo |

Juntos, en **Pages › Dot 2 › Operaciones**.

## Un ejemplo

```tsx
import { DotUptime, Pipeline, Stat, Status } from "desing";

<Status tone="error">notificaciones caído</Status>
<Stat label="Error budget" value="64 %" delta="−18 pp" trend="negative" note="Quedan 16 días" />
<DotUptime periods={dias} label="Disponibilidad, 30 días" />
<Pipeline
  label="Despliegue #482"
  stages={[
    { id: "build", label: "Compilar", status: "ok", meta: "1 min 12 s" },
    { id: "canary", label: "Canario 10 %", status: "running" },
    { id: "prod", label: "Producción", status: "idle" },
  ]}
/>
```

Para informes y consolas, activa **Dot 2** con `data-pt-version="2"`: papel en vez de vidrio y
un solo color de acento. Está en **Dot › Versión 2**.

## Cinco reglas

1. **Todo es un punto.** Rejilla de 4 px, puntos cada 8. El punto hace de textura (`DotField`),
   de estado (`DotLoader`, `DotProgress`), de dato (`DotBars`, `DotUptime`) y de separador.
2. **El color, para lo que importa.** Un estado caído, un botón principal. Lo demás es _mist_
   (claro) o _ink_ (oscuro). Si todo es rojo, nada es urgente.
3. **Vidrio encima del ruido.** En v1 los paneles son vidrio esmerilado (`GlassCard`) sobre los
   puntos; en v2, papel con un filete.
4. **Tres voces.** _Instrument Serif_ para titulares y cifras grandes, _Inter Tight_ para la
   interfaz e _IBM Plex Mono_ para todo lo que se copia: hashes, rutas, versiones.
5. **Movimiento lento y opcional.** Nada parpadea. Todo respeta `prefers-reduced-motion` y los
   lienzos se pausan fuera de pantalla: el portátil de guardia ya sufre bastante.

## Paletas

El lenguaje no depende de un color: los componentes leen roles (`--pt-bg`, `--pt-accent`…) y un
espectro de seis tonos (`--pt-spectrum-1…6`). Una paleta reasigna los neutros y el espectro con
`data-pt-palette`, en el mismo elemento que `data-pt-theme` (o en uno superior):

```html
<html data-pt-theme="light" data-pt-palette="siena">
```

| Paleta    | Neutros                    | Espectro                       | Carácter            |
| --------- | -------------------------- | ------------------------------ | ------------------- |
| `punto`   | lavanda · tinta violácea   | violeta → magenta → coral      | Expresivo (original) |
| `marea`   | niebla marina · azul marino | azur → turquesa → verde mar    | Sereno, técnico     |
| `siena`   | papel hueso · tinta café   | vino → terracota → ocre        | Cálido, editorial   |
| `citrico` | piedra · negro oliva       | esmeralda → lima → oro         | Fresco, enérgico    |
| `mono`    | blanco puro · negro puro   | grises; color solo en estados  | Brutalista          |

`mono` trae además su forma: esquinas rectas, trazo de 2 px en tinta y sombra dura en vez de
vidrio (`mono.css`). Es la buena para un informe que se va a imprimir o a pegar en un ticket.

Cada paleta tiene su textura de héroe en `DotField` (`aurora`, `marea`, `siena`, `citrico`, `mono`;
`heroDotPalette(nombre)` la devuelve) y funciona en _Mist_ y en _Ink_. Compáralas en
**Foundations › Palettes** o cambia la de todo el Storybook con el selector **Paleta**.

## Variantes de la textura

| Paleta     | Uso                                                              |
| ---------- | ---------------------------------------------------------------- |
| `aurora`   | Portadas y héroes. La versión completa, con todo el color.       |
| `ember`    | Solo cálidos (magenta, coral). Estados positivos, campañas.      |
| `dusk`     | Solo fríos (índigo, violeta). Secciones técnicas, modo análisis. |
| `graphite` | **Sobria.** Puntos de tinta sobre mist. Producto, dashboards.    |
| `night`    | **Sobria** en oscuro. Puntos claros sobre ink.                   |
| `paper`    | **Casi invisible.** Un fondo con textura, no una imagen.         |
| `marea` · `siena` · `citrico` · `mono` | Héroes de las paletas alternativas (`monoNight` para Mono en oscuro). |

Y tres movimientos: `flow` (las cintas se desplazan), `breathe` (quietas, solo pulsan la
intensidad) y `still` (un único fotograma).

## Estructura

- **Foundations** — color, tipografía, forma y movimiento como tokens CSS (`--pt-*`).
- **Dots** — la familia de puntos: `DotField`, `DotPattern` (el patrón compuesto de v2),
  `DotLoader`, `DotProgress`, `DotBars`.
- **Components** — `Button`, `Badge`, `GlassCard`, `TextField`, `Segmented`, `Sparkle`,
  `Petals`, `DotMark`.
- **Transversales** — piezas para montar pantallas sin CSS propio: `Stack` (layout en la
  rejilla de 4 px), `SectionHeader` (eyebrow + titular + acciones), `Stat` (KPI con su gráfico
  de puntos), `Callout` (mensajes con borde de puntos), `Switch`, `Avatar` / `AvatarGroup` y
  `DotDivider` (el separador de puntos).
- **DevOps** — piezas para consolas y paneles de operación: `Status`, `DataTable`,
  `KeyValue`, `CodeBlock`, `LogView`, `Pipeline`, `Diagram` y, en Dots, `DotUptime`.
- **Tema** — `ThemeSwitch` y `useTheme()` para el selector de modo noche (sistema, claro,
  oscuro, OLED).
- **Pages** — un póster de estado, una pantalla de despliegue (`Product`), el panel de guardia
  (`Workspace`) y, en **Dot 2**, un informe semanal, un post-mortem y una consola de plataforma.

> **Dot 2.** La versión sobria, con patrones quietos en vez de cintas, convive con esta: está
> en **Dot › Versión 2** y se activa con `data-pt-version="2"` o con el selector **Versión**.

En la barra superior, **Tema** alterna _Mist_ (claro), _Ink_ (oscuro) y _OLED_ (negro puro), y
**Paleta** cambia de paleta.
